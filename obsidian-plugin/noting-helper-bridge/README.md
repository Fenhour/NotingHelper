# Noting Helper Bridge

NotingHelper 随附的 Obsidian 桌面插件，当前版本 **2.5.4**。提供 Markdown/PDF 选区捕获、来源定位、高光浮层、注释、标签、图片及 Markdown 导出。

## 安装与更新

在桌面助手点击“更新插件”，确认自动检测到的目标仓库，或手动选择需要更新的仓库。记录问题与高光可以使用不同仓库，安装目标不改变两套功能配置。

在 Obsidian 的社区插件设置中启用 `noting-helper-bridge`。更新已启用插件后，关闭再开启插件或重启 Obsidian；复制文件不代表运行实例已更新。

手动安装时，将 `main.js`、`manifest.json` 和 `styles.css` 放入仓库的 `.obsidian/plugins/noting-helper-bridge/`。保留已有的 `data.json` 与 `storage/` 数据。

## 划选与高光

- Markdown 编辑视图按精确字符偏移定位；阅读视图在唯一上下文内定位。
- PDF 使用当前 PDF.js 选区、页码及页内出现次序；跨页选区不保证。
- 原生色盘与桌面后备色盘直接使用插件捕获的选区，添加高光不经过剪贴板。
- 桌面记录问题、记录单词可以使用插件提供的选区快照；桥接无法提供文本时，桌面端仅在用户点击具体记录按钮后回退复制。
- 配置中的三种入口颜色只控制新增/换色入口，历史高光继续保留原有颜色。

添加高光只保存记录并绘制浮层，源 Markdown/PDF 保持原样。明确执行“标注来源”时，Markdown 块定位可能插入块 ID；重复文本或位置不确定时拒绝猜测。

## 注释编辑

在侧栏点编辑按钮就地编辑，或从正文高光菜单打开弹窗。可输入标题、正文、标签，以及通过文件选择或 Ctrl+V 添加图片。删除图片占位行再保存会解除关联，历史图片不自动物理删除。

代码转换与桌面记录问题一致：先在正文选中文字，再打开“代码块”菜单，选择自动推荐或指定语言。没有选区或只选中空白时提示并保留正文。浏览菜单时保持原生选区高光，转换完成后收起；保留缩进，已有反引号会使用更长围栏。预览、保存和导出保留代码格式。

## 侧栏筛选与定位

顶部提供当前/全部文档范围开关、颜色筛选和文字搜索。

颜色候选包含“全部”及所有文档现有高光记录中的颜色，历史记录优先按实际颜色快照归类，与配置的三种入口颜色无关。候选不被当前文档、搜索词或已选颜色缩减。

颜色筛选与范围、搜索共同生效；文字搜索沿用跨文档规则。删除某颜色最后一条记录后移除候选，若正选中该颜色则回到“全部”。正文“跳转侧栏”会解除挡住目标的筛选并定位卡片。

## 数据与导出

唯一实时日志位于插件目录的 `storage/highlights.jsonl`，图片位于 `storage/imagehighlights/`。修改/删除通过同一 ID 的日志事件处理；删除高光不会擦除历史日志或源文件。

单条导出和完整导出按需生成 Markdown 索引、注释文档及图片副本，可写入另一个 Obsidian 仓库。跨库导出要求来源库运行 2.5.1 或更高版本；目的库不必启用插件。导出只管理自身生成的文件，不清理用户来源文档。

## 开发

```powershell
npm ci
npm run build
```

`source.js` 为源码，`main.js` 为随附构建文件。Obsidian 和 CodeMirror 依赖在构建时保持 external，运行时使用 Obsidian 提供的模块。

在项目根目录运行：

```powershell
node tools/test_obsidian_plugin.js
node tools/test_obsidian_editor_dom.js
```

自动测试覆盖桥接、编辑器、PDF 和侧栏逻辑；真实 Obsidian 的选区视觉与鼠标操作仍需人工验证。
